# 极跃棋牌 · 企业级架构设计

## 一、总体架构

采用**三端分离 + 单一后端服务**架构：

```
Web 管理后台(admin-web) ─┐
                          ├─→ REST API ─→ 后端服务(server) ─→ 数据层(db.json)
桌面客户端(desktop) ─────┘         │              │
                              Socket.IO     游戏引擎
                                             ├─ 斗地主(GameEngine)
                                             └─ 麻将(MahjongEngine)
```

- **Web 管理后台**：仅供运营人员，纯管理功能，不含游戏。
- **桌面客户端**：玩家游戏入口，Electron 封装，含斗地主/麻将全部玩法。
- **后端服务**：REST 业务 + Socket 实时对战 + 企业级管理 API。

## 二、后端分层

| 层 | 目录 | 职责 |
| :--- | :--- | :--- |
| 接入层 | `routes/`、`admin/routes.js` | HTTP 路由、鉴权、权限校验 |
| 业务层 | `services/`、`admin/*.js` | 用户/经济/房间/商城/报表/风控 |
| 领域层 | `game/`、`mahjong/` | 游戏规则引擎 + AI + 状态机（纯逻辑，无 IO） |
| 实时层 | `sockets/` | 对战同步、AI 调度、聊天、超时托管 |
| 数据层 | `db/store.js` | JSON 持久化（接口稳定，可替换 ORM） |

## 三、企业级子系统

### RBAC 权限模型
- 管理员独立于玩家账号体系（`admins` 集合）。
- 角色 → 权限点映射（`rbac.js` 的 `ROLES`）。
- `resolveAdmin` 解析身份，`requirePerm` 校验权限点，越权写审计。
- 兼容存量玩家表 admin 账号（token role='admin'）。

### 审计日志
- 追加写、不可篡改（`auditLogs` 集合）。
- 记录：操作人、角色、IP、动作、对象、详情、时间。
- 覆盖：登录、RBAC 变更、封禁、发放、风控处理、配置修改、房间解散。

### 风控规则
- 单局金币变动异常（>5万/20万分级）。
- 频繁破产补助（≥5次/10次分级）。
- 金币异常膨胀（>500万）。
- 处理结果独立存储（`riskHandled`），扫描时合并。

### 数据报表
- 按天聚合：对局数、新用户、金币流动、营收、游戏分布。
- 留存率：次日/3日/7日（基于注册与最后登录跨度）。
- 用户分层：核心/活跃/普通/未开局。

### 配置中心
- 默认值来自 `config/index.js`，覆盖值存 `systemConfig`。
- 支持单条/批量更新，热生效。
- 分组：经济/游戏/麻将/系统。

## 四、实时对战设计

- Socket 按 `user:<userId>` 分房推送状态，保证每个玩家只看到自己的手牌。
- `snapshot(selfSeat)` 按座位生成：**关键约束**——必须传 seat 数字而非 userId。
- AI 调度：`afterChange` 统一处理，引擎 `change` 事件自动回调，**避免手动重复调用**。
- 超时：真人超时自动托管；AI/托管走 `aiThinkMs()`（可配 `AI_THINK_MS` 加速）。
- 结算：`handleFinish` 统一落库（金币/战绩/任务进度）+ 广播 + 轮庄重开。

## 五、扩展方向

- 数据层：`store.js` 接口稳定，可替换为 MySQL/Prisma + Redis。
- 网关：多实例部署时 Socket 需接 Redis Adapter。
- 配置：接入 Nacos/Apollo 替代本地配置。
- 监控：接入 Prometheus + Grafana，日志接 ELK。
