# 授权壳 App 使用说明（完整版）

> 这套系统分三件，**缺一不可**：
> ① 网站后台（发激活码 + 验激活码）　② 授权壳 IPA（用户装上去加壳用）　③ 验证插件 dylib（注入进目标 IPA 的核心）

---

## 一、这套系统到底怎么运转（先看懂再动手）

```
【你 / 作者】
   1. 网站后台建应用 → 得到 AppKey / AppSecret
   2. 后台生成激活码 → 发给用户
   3. 把「授权壳 IPA」发给用户（就是 GitHub 编译出来的那个）

【用户】
   4. 用全能签给「授权壳 IPA」签名 → 装到自己手机
   5. 打开壳 App → 填你的服务器地址 + 账号 → 连上后台 → 选中你的应用
   6. 点「选择 IPA」→ 选中自己想授权的那个 IPA
   7. 点「一键植入授权插件」→ 壳 App 在本地把验证 dylib 注进去 → 导出新的 IPA
   8. 点「自动签名并一键安装」→ App 静默完成重签 → 客户直接点安装（全程不碰证书）
   9. 打开新 IPA → 弹激活码输入框 → 输入第 2 步你给的激活码 → 激活成功，正常使用

> 客户拿到成品后**唯一的动作就是输激活码**，签名/安装全部由壳 App 自动完成、客户无感。
```

**最重要的一条认知**（很多人在这里绕晕）：

| 常见误解 | 实际情况 |
| :--- | :--- |
| 加壳要传到服务器加工 | 加壳全程在**用户手机本地**完成，服务器只发码、验码 |
| 客户要自己导证书签名 | 不用。壳 App 内置自动签名，客户加壳后点「一键安装」即可，全程不碰证书 |
| 激活码是输进壳 App 的 | 激活码是输进**加壳后生成的新 IPA** 的 |
| 激活判断在服务器上弹窗 | 弹窗在目标 IPA 里（验证 dylib 干的），服务器只返回"通过/拒绝" |

**"直接安装"的技术本质**：iOS 装任何 App 都要有效签名。所谓"客户直接装"，是因为新 IPA 用**你的分发证书**（企业签/超级签）静默重签了——客户设备上早已信任这套证书，所以无感。签名这件事被壳 App 自动化了，不是消失了。

## 二、你（作者）要先做的三件事

### 1. 把网站后台部署到公网

壳 App 和新 IPA 都要连你的服务器，所以后台必须是**公网可访问**的地址（`http://` 或 `https://` 都可以，壳 App 内部已放行 HTTP）。

```bash
cd server
npm install
PORT=8080 node app.js
```

- 后台管理地址：`http://你的服务器IP:8080/`
- 默认管理员：`admin` / `admin123`（登录后立刻改密码）
- 用 Nginx 反 + 域名 + HTTPS 更稳，见 `docs/DEPLOY.md`

### 2. 建一个应用，拿到密钥

后台 → **应用管理** → 新建应用 → 记下生成的：

- `AppKey`：形如 `AK_XXXX`
- `AppSecret`：一长串密钥

这两个值会由壳 App 自动写进新 IPA，用户看不到、改不了。

### 3. 生成激活码发给用户

后台 → **卡密管理** → 选应用 → 选类型 / 有效期 / 设备上限 → 生成 → 把激活码发给你要授权的用户。

## 三、编译出「授权壳 IPA」（GitHub 自动编译）

你不用买 Mac、不用装 Xcode。把项目传到 GitHub，云端 macOS 机器会自动编译好 IPA 给你下载。

### 步骤

1. 在 GitHub 新建一个仓库（比如 `ipa-shell`）
2. 把整个 `ipachajian` 目录传上去（一键脚本见下）
3. 进入仓库 → **Actions** 标签 → 左边点 **编译授权壳 IPA** → 右边 **Run workflow** → 绿色按钮
4. 等 3～8 分钟，跑完后在本次运行的页面底部 **Artifacts** 里下载 `IPAShell.zip`
5. 解压得到 `IPAShell.ipa` —— 这就是发给用户的「授权壳 IPA」

### 一键上传到 GitHub（Windows）

双击运行 `上传GitHub.bat`，按提示填你的仓库地址即可。脚本内容：

```bat
@echo off
set /p REPO=请输入你的GitHub仓库地址(如 https://github.com/你的名/ipa-shell.git)：
git init
git add .
git commit -m "IPA授权系统"
git branch -M main
git remote add origin %REPO%
git push -u origin main -f
echo 上传完成！去 GitHub 仓库的 Actions 页面手动触发编译。
pause
```

> 首次推送会弹 GitHub 登录框（或需要 Personal Access Token），按提示登录一次即可。

## 四、用户侧完整操作流程（照着做就行）

| 步骤 | 用户操作 | 说明 |
| :--- | :--- | :--- |
| ① | 填服务器地址、后台账号密码 → 点「连接后台」 | 地址填你公网后台，如 `https://verify.xxx.com` |
| ② | 在应用选择器里选中你的应用 | AppKey / AppSecret 自动带入，用户不用手填 |
| ③ | 点「选择 IPA」→ 选中要授权的 IPA | 就是用户自己想加壳的那个 App |
| ④ | 点「一键植入授权插件」 | 本地完成：解压→注入→写配置→打包 |
| ⑤ | 点「自动签名并一键安装」⭐ | App 静默重签 + 拉起安装，客户全程不碰证书 |
| ⑥ | 打开新 IPA → 输激活码 → 激活成功 | 输的是你后台发的码，之后自动放行 + 收远程公告 |

**客户全程只做 6 步、只手输一次激活码。** 签名和安装由「分发签名服务」（作者在系统设置里填一次地址）自动完成。

### 分发签名服务怎么接（作者配置一次）

壳 App 的「分发签名服务地址」填你签名接口的地址即可，接口约定：

```
POST  https://你的签名服务/api/sign
Body: multipart/form-data，字段 ipa = 加壳后的成品 IPA
返回: {"code":0,"data":{"install_url":"itms-services://..."}}
      或 {"code":0,"data":{"manifest_url":"https://.../manifest.plist"}}
```

签名服务用你的企业签/超级签证书重签后，返回一个 `itms-services` 安装链接（或 manifest 地址），壳 App 自动拉起安装。这一步在你自己的分发平台上完成，证书不出你的服务器。

## 五、常见问题

**Q：为什么连不上后台？**
A：服务器地址要写完整（`https://` 开头或 `http://` 都行），手机和你服务器网络要通。后台默认 8080 端口，云服务器安全组记得放行。

**Q：加壳后的 IPA 装不上 / 一打开就闪退？**
A：三个原因——① 签名服务地址没填或签名服务不可用：在壳 App 里填好「分发签名服务地址」；② 目标 IPA 架构不符：壳 App 是 arm64，目标 IPA 通常也是 arm64，正常没问题；③ 目标 IPA 本身加了壳/加密（如 App Store 加密），需先用砸壳版。

**Q：激活码输错了会怎样？**
A：验证 dylib 连续失败 3 次会自动退出 App，防止绕过。

**Q：能改有效期、冻结卡密、发公告吗？**
A：都能，在网站后台操作，详见 `docs/API.md` 和后台界面。

**Q：GitHub 编译要钱吗？**
A：公开仓库的 Actions 有免费额度，个人用量完全够。
